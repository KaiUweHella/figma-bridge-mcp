# Own Composite Typography and Shadow Style Import

Generic source and simple DESIGN.md import project Typography and Shadow facts
into one versioned Composite Style Import source before Plugin readiness. The
projection accepts bounded Text and Effect Style intent, keeps structured
effects as official union objects and lists every construct without an exact
owned mapping as explicit unsupported evidence. It never flattens a composite
into a simple Variable or claims an unsupported field was imported.

The Plugin loads the complete bounded local Text Style, Effect Style and
Variable catalogs. Exact source id or key is authoritative when supplied;
otherwise exact family-local name is identity. Ambiguity, conflicting source
identity, different description, authored Style fields, binding topology or
Variable type fails before mutation. Every referenced Text Style Variable and
every unique font face resolves before the first Style factory call.

Exact existing Styles are no-ops. Missing Text and Effect Styles are created
sequentially and journaled immediately, then receive metadata, native property
objects and supported scalar Text Style bindings. A later assignment, binding
or fresh-read postcondition failure removes the complete command-created Style
journal in reverse. Failed cleanup returns bounded typed residue and never
claims atomicity. Existing Styles are never implicitly updated.

CSS and Tailwind shadow strings are parsed into ordered DROP_SHADOW or
INNER_SHADOW objects; multi-layer order is retained. W3C composite field
references retain compatible Text Style Variable aliases after the referenced
Variable exists. Effect binding aliases remain explicit unsupported evidence
until an exact owned mutation and rollback contract exists.

Variable creation and Composite Style creation remain separate deep
transactions called behind one Design Source Import Command Plan. A Style
failure rolls back command-created Styles, not Variables already committed by
the preceding exact Variable transaction; its failure evidence remains
explicit rather than presenting the whole import as atomic.
