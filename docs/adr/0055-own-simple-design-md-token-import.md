# Own Simple DESIGN.md Token Import

`tokens import-design-md` classifies an authorized document after one bounded
parse. A document without a non-empty multi-Collection Variable Snapshot
projects COLOR, radius and spacing facts into the existing deep
Single-Collection Token Import implementation. CLI and MCP keep the original
DESIGN.md Command Plan and one non-retrying Audit lifecycle; the mutation does
not create a nested synthetic token-file Plan.

The projection and complete Token Import normalization finish before Plugin
readiness. Collection ambiguity, duplicate projected names, invalid values and
unsupported shapes therefore fail before the first Figma write. The existing
mutation journal, declared-default-mode selection, exact no-op matching, fresh
postconditions and bounded rollback evidence remain unchanged.

Typography and shadow composites are not flattened into simple Variables.
They remain in bounded agent context and produce an explicit warning until
dedicated Text Style and Effect Style transactions can preserve their native
facts. A document containing only those composites stays useful without Plugin
dispatch. Collection names containing `/` require the same explicit
`--force-slash` intent as JSON Token Import.

A non-empty `tokens.variables` block remains on the existing compatibility
Adapter for this slice. It is not a simple Single-Collection import: Collection
identity, multiple modes and cross-Variable aliases need their own versioned,
journaled transaction. The compatibility route is preserved until that
separate migration lands rather than silently degrading a snapshot into one
mode or one Collection.
