# Own Generic Design Source Import

The top-level `import <source>` Interface is one Design Source Import Command
Application. Its closed request preserves source, optional Collection, context
projection, explicit output, source-type override and Collection slash intent.
CLI and MCP canonicalize that request into the same immutable Command Plan and
one payload-free Audit lifecycle.

The Plan authorizes only the original local source and an explicitly supplied
`--save` destination. Source detection and conversion receive that exact
WorkspaceIO capability; they cannot establish a second ambient workspace
authority. Storybook URLs continue through the separate bounded remote policy.
No default `DESIGN-storybook.md`, temporary DESIGN.md or synthetic token-file
role is created.

Preparation completes before Plugin readiness. `--print-context` has no Figma
target, confirmation or Plugin dispatch and needs only readable WorkspaceIO
unless `--save` is explicit. Storybook or sources containing only unsupported
composites may also resolve to repository context without dispatch after
bounded conversion.

Simple COLOR, radius and spacing facts become prepared Single-Collection Token
Import items in memory. The Design Source Import Application calls the deeper
journaled mutation directly behind the original Plan instead of creating a
nested Plan or re-entering Commander. DESIGN.md delegates to its prepared
simple or exact Variable Snapshot implementation on the same principle;
legacy v1 snapshots remain on their explicit compatibility route.

Collection names containing `/` require `--force-slash`. Derived Collection
names remain bounded and pass through the same normalization and ambiguity
checks as direct Token Import. Supported Typography and Shadow composites reuse
the dedicated native Composite Style Import transaction behind the same outer
Command Plan and Audit lifecycle.
