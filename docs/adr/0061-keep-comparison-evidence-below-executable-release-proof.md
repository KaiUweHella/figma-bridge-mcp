# Keep comparison evidence below executable release proof

Figma Bridge benchmarks its accepted Fidelity Corpus against exact pinned
comparison identities, but another implementation remains a test-case source
rather than the target architecture. Every comparison direction records one
capability, evidence level and limitation class. Source inspection and official
documentation can establish declared coverage or a product boundary; neither
can produce a Fidelity Run score.

Access, product and evidence limitations remain distinct. A missing supported
client cannot be reported as an unsupported product feature, and an absent
feature cannot be hidden as an access issue. Only Bridge cells are required to
resolve to local executable tests and registered Evidence IDs. Useful external
behavior becomes an existing or tracked Bridge requirement before any
implementation work is scheduled.

Selected comparison configurations must not enable private APIs, host binary
patches or browser-debugging transports. The historical CLI is therefore
audited in its built-in Safe Mode, while other upstreams may remain source- or
documentation-only. Missing live access is preserved honestly instead of
weakening the security boundary to manufacture parity evidence.
