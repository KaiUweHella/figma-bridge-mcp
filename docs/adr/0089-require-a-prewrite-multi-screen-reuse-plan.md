# Require a pre-write multi-screen reuse plan

Multi-screen rendering previously emitted advisory repeated-structure and
inventory hints, but a caller could optimize for root throughput and still
leave repeated raw trees. A console warning was not acceptance evidence and
the final Outcome did not say what was reused.

Every compound multi-root request now derives one content-free reuse plan
before Plugin readiness. Explicit Design Entity Instances are counted across
all roots. Repeated raw Frame structure is represented by a stable truncated
SHA-256 Finding ID, bounded occurrence count and root indexes; source text and
names are not retained in that evidence. Descendant findings fully contained
inside an already reported repeated structure are suppressed.

An unapproved flat repetition stops before the first Figma write and gives two
actions: create or link one component and use Instances, or approve that exact
current Finding ID. Unknown, stale and wildcard approvals fail closed, so an
exception cannot disable later reuse findings. Intentional one-off screens and
explicit vertical review layouts remain available.

The successful Semantic Render Outcome includes the reuse plan's component
entities, Instance count, components created by an explicit conversion stage
and approved flat repetitions. Smart row placement remains the screen default
and starts to the right of occupied canvas content; column placement remains
an explicit option.
