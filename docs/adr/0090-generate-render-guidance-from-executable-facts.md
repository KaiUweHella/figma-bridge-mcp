# Generate Render guidance from executable facts

Public Code-to-Figma guidance must not maintain a second description of
Semantic JSX or native executor support. The closed element/property grammar
owns valid props and reviewed aliases. Native structured preflight owns the
Instance identity and host-materialized Image requirements. A small Semantic
Render Guidance Contract projects only those content-free facts together with
generic Command and JSX examples.

The MCP Code-to-Figma workflow formats its Instance and Image section directly
from this Contract. Every embedded `figma_run` argv and JSX example is retained
as structured data and crosses the current Command/request and Semantic Render
Plan boundaries in CI. README and packaged skills may add surrounding prose,
but tests reject name-based Instance syntax or Image-placeholder success claims
that conflict with the Contract.

An Instance example therefore authors only `entity` plus variant/override
intent. The preceding `link set` example makes the default repository manifest
step explicit. Published keys and exact-file node ids remain Plan-owned binding
facts, never author syntax. An Image with `src` is host-materialized as bounded
`embedded-raster` bytes and stays native. An Image without `src` remains useful
as a deliberate compatibility placeholder, but guidance must name its
`completed-with-findings` Outcome and exact native-preflight reason.

This keeps guidance changes mechanically coupled to behavior changes without
making documentation generation a Figma-side effect or widening the public
grammar.
